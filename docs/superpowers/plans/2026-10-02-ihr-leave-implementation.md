## Global Constraints

- Scope is annual leave only, with three views: Cuti Saya, Persetujuan and Kalender Tim, plus separately authorized HR settings. No attachments, medical-certificate collection, payroll, clock-time intervals, partial cancellation, carryover, automatic accrual or new notification subsystem.
- Exact integers: annual grant 5,400 minutes; weekday 450; scheduled alternate Saturday 225; half-day 225; fixed choices 60, 120, 180, 240, 300 or 360. One duration selection applies across a request. Full scheduled-day mode resolves independently to the day's capacity. Fixed requests exceeding any included working day's capacity fail as a whole, never clip.
- Established eligible staff receive the full grant on January 1 once per employee/type/year. Calendar-year accounts are [January 1, next January 1). Future-year booking stays blocked unless an authoritative eligible account and configured horizon exist. New-hire first entitlement stays blocked until separately reviewed; never infer employment/eligibility from Auth, invitation or login timestamps.
- Directors are approval-only. No personal leave, new account, grant or submission. Managers approve explicitly assigned employees; directors approve explicitly assigned managers. One-step approval; no self-approval; application role or ordinary HR configuration is not request approval authority.
- Real employee classifications, start/eligibility dates, HR grants, timezone, rota groups/anchor/mappings/coverage, opening positions, holidays, visibility, notice/reason/cancellation rules, retention and access-review rules remain explicit setup blockers. Access-review approval evidence must identify the exact approved rule/version, approving identity/date, accountable review owner, approved cadence and covered grant/capability/data audience scopes. Any unset or unconfirmed value blocks real-data enablement; do not infer an owner, cadence or audience from application roles or fictional fixtures. Use fictional UUID fixtures only. Sunday capacity is unconfirmed null or explicit confirmed zero, never silently enabled.
- Pending requests reserve allowance. Exactly one active request may occupy each employee/date. Approval converts reservations to usage; rejection/withdrawal releases reservations/occupancy. Approved and cancellation-pending requests retain usage/occupancy until accepted whole cancellation. Refund exactly once to original accounts; expired credits are not current-year spendable allowance.
- SQL owns eligibility, authority, calculation, immutable snapshots, concurrency, idempotency and transitions. The browser is never authoritative. Use non-retryable business conflicts such as SQLSTATE 55000, never transaction retry SQLSTATE 40001. Preserve existing PO PT409 handling.
- Enable RLS, explicitly revoke client direct writes and private helper execution, use fixed safe security-definer search paths, and derive actor/time from authenticated database state. Deny anonymous, inactive, unrelated and guessed-ID access without distinguishable private-data leaks. Never broaden sales/PO helpers or storage policies.
- Separate configure, adjust, read_private, calendar and access-management grants, each with audience scope. No own access expansion, own approver appointment, own eligibility edit or own entitlement adjustment. Do not bootstrap any actual HR permission.
- Calendar/roster/membership/assignment/policy changes are effective-dated and audited. Approved history retains frozen source/charge/period snapshots. Relevant source changes make pending approval stale rather than recalculating or silently reassigning it.
- Keep one confirmed timezone per calendar lineage. Unconfirmed drafts cannot erase a known timezone or silently change it. Use the authoritative lineage timezone for edit cutoffs and company-local today. Current selected unconfirmed source still blocks charge calculation.
- Mutation isolation is READ COMMITTED, command/reconcile VOLATILE. Refresh current active actor, grants and one clock_timestamp authorization instant after every relevant blocking lock. Document a consistent order: actor/key command lock, global setup lock where needed, sorted employee assignment locks, scope revision, sorted employee occupancy locks, request/account locks in fixed order, ledger/audit. Do not acquire occupancy after account locks.
- Private reasons, notes and detailed calendars never enter logs, analytics, errors, browser persistent draft storage or recovery metadata. Recovery stores only UUID, hash, uncertainty/minimal result, keyed by backend, actor and form scope. Reconcile before a different attempt; retain terminal abandonment tombstones.
- Query keys include backend, actor, authorization scope/version, filters and range. Cancel/discard obsolete reads and purge sensitive caches on identity/scope change. Another observer of the same identity must not purge current observers. Refresh authority on foreground/visibility and before interaction, with bounded 60-second foreground polling where required.
- Integrate AuthContext, App and Athel/Girard navigation under this plan's single owner. Employee entry must not route to executive-only /landing or expose User Management. /ihr/users retains existing restrictions. Keep category work separate and preserve canonical PO/photo behavior.
- Work only in the new isolated worktree. One active implementation/review/setup helper at a time. Fresh implementers per task, independent reviews, focused test evidence per task, aggregate integration once; maxWorkers=1 and coordinate aggregate slots. Rebuilt bytes need new tests/reviews, never reuse lost-byte evidence as proof.
- Local SQL is only an owned synthetic loopback PostgreSQL 17 cluster, database pilot_test and verified disposable-pilot-ci marker. Guard failures launch no workload. Never spoof GitHub identity or loosen existing import guards. No hosted migration, remote publication, credential creation, data configuration or access expansion without exact later approval.
- Seven additive unpublished HR candidate migrations may be corrected/recreated during owned synthetic iterations, with per-run hashes. Never modify published/canonical migrations. Preserve literal migration inventory by deliberate union at final integration. Rollback/disable must preserve ledger, audit, charge history and tombstones.
