# Decision and cancellation race execution contract

This recipe and adapter are unexecuted until the coordinator's owned, marker-checked PostgreSQL 17 loopback job runs them. Do not use hosted targets or change guard policy. Use a fresh pilot_test database with the complete candidate migration closure including the composed decisions module. The unchanged runner receives tests/database/ihr/decisions-concurrency.mjs as its --race adapter. The adapter verifies the marker before loading decisions-race-fixture.sql, whose source closure is quote-seed.sql, seed.sql and accounts-seed.sql.

The six synthetic cases are approve versus reject, withdrawal versus approve, rejection versus approve, cancellation acceptance versus decline, two acceptances under the same command UUID, and manager deactivation committed while approval waits for the original account advisory lock. All racing sessions call the genuine public command/reconcile RPCs as authenticated with distinct connections/PIDs and fictional JWTs; helpers assert actual non-superuser/non-bypass roles.

For each competing decision, A begins, runs the command and keeps its transaction open after printing A_HELD. B starts the competing command. The coordinator adapter must observe B's recorded PID in pg_stat_activity, wait_event_type Lock, wait_event advisory, an ungranted advisory pg_locks row, and A's PID among pg_blocking_pids(B). Only then may A COMMIT. B must receive SQLSTATE 55000 for a distinct losing key, or the exact original receipt for the same accepted-cancellation key. Both streams must finish cleanly. Independent final state verifies the expected version/status, exact occupancy, net reservation/usage, exactly one winning command, no losing command and exactly one cancellation reversal where applicable. A's post-commit replay and reconciliation must return the same minimal receipt.

For revocation, a dedicated owner holder acquires ihr-account:<employee UUID>:<original year>, then the manager command begins. Observe the same actual advisory blocker barrier before deactivating public.users.is_active in another owner transaction. The owner revocation must commit while the approval remains blocked. Release the holder only after that commit. The command must fail 42501, retaining submitted/version1, reservation450, usage0, occupancy1 and no new command/event/ledger transition. A held scope row that prevents revocation is a failure, never a reason to reverse the ordering or accept stale authority.

The adapter's hard process deadline, server statement/lock timeouts and finally teardown reap all child psql processes. Invalid targets are refused before spawn. A fixed sleep is never contention evidence. IHR_DECISIONS_CONCURRENCY_PASSED is emitted only after all barriers, receipts and final-state assertions. Report exact commit/tree/module and fixture hashes with runtime evidence; static tests and this recipe do not establish SQL runtime acceptance.

## Round 1 lifecycle and exact outcome correction

SIGINT, SIGTERM, watchdog expiry and process/stream errors now use the same idempotent owned-child cleanup path as the separately reviewed request adapter at 3b72dff. Work stops immediately; only recorded children receive TERM, then KILL after the bounded grace. Error/exit notifications do not count as reaping: only terminal close resolves the reap promise. A hard cleanup deadline returns an explicit unverified-cleanup failure for any remaining child and never emits the success marker. Signal listeners and timers are removed after cleanup. Controlled ChildProcess-event tests exercise interruption, delayed close, missing close, spawn errors and the absolute watchdog without launching a database or subprocess.

Before each competing decision, the owner records a complete JSON snapshot of all synthetic request rows, days, allocations, occupancy, accounts, ledger entries, events, command envelopes, cancellation attempts, decisions and reversals. The winner must have exactly the expected request status/version change, one account-version increment and exact reserved/used delta per original allocation, exactly one matching transition ledger row per allocation, one precise private request event and one original command envelope. Every existing row is preserved byte-for-value except the named allowed delta; no other command, event, ledger or snapshot effects are permitted. Cancellation additionally requires the exact accepted attempt and original-charge/reversal links. A second snapshot after the winning command's replay and reconciliation must equal the complete post-winner snapshot.

The post-account-wait denial compares the entire relevant snapshot unchanged, allowing only the intentionally changed users.is_active/scope revision outside these request/account tables. These comparisons supply booleans to the genuine authenticated assertion helpers; private fixture snapshots are retained only in memory and never printed. IHR_DECISIONS_CONCURRENCY_PASSED follows all comparisons and verified cleanup. The producer's unit tests of the comparison and lifecycle are not actual PostgreSQL race evidence.
